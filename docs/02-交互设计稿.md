# APK Parser Toolkit — 交互设计稿

> 版本：v0.1（设计评审稿）
> 配套文档：`01-需求设计稿.md`、`03-技术方案.md`
> 可点击原型：`docs/prototype/index.html`

---

## 1. 设计原则

| 原则 | 落地方式 |
|---|---|
| **一眼看到重点** | 所有「信息展示」界面，顶部固定一条 **关键信息条**（包名 / 版本名 / 版本号 / 目标 SDK），字号最大、可一键复制，永远不因滚动而消失 |
| **两下完成** | 高频动作（解析、安装、启动、截图）最多两次点击；不设多步向导 |
| **不猜命令** | 每次执行前后都能看到**真实命令**，可复制、可追溯 |
| **不静默失败** | 任何失败必须给出：发生了什么 + 为什么 + 怎么办 |
| **不打断** | 长任务（安装、录屏）不锁界面；不弹系统模态框，用内联进度 |
| **不学就用** | 首屏空态给出「现在可以做什么」的引导，而不是空白 |

## 2. 交互载体总览

工具不是「一个界面」，而是**四种载体按场景分工**。这是本设计的核心结构：

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 主控台（常驻 Web UI）  复杂交互、列表、参数编辑、捕获、安装管理        │
│    http://127.0.0.1:5170        ← 启动命令: apktool.py web             │
├──────────────────────────────────────────────────────────────────────┤
│ ② 轻弹窗（右键触发）     单文件信息卡，秒开秒关，无需常驻进程            │
│    右键 .apk → 解析信息                  ← apktool.py info --popup     │
├──────────────────────────────────────────────────────────────────────┤
│ ③ 控制台窗口（双击触发） 实时日志流、安装反馈、带颜色的成败结论          │
│    双击 .apk → 安装                      ← apktool.py install --console│
├──────────────────────────────────────────────────────────────────────┤
│ ④ 命令行（脚本/CI）      全能力可达，--json 供程序消费                  │
│    apktool.py <子命令>                   ← 可接入你已有的 D:\bat\*.sh   │
└──────────────────────────────────────────────────────────────────────┘
```

**设计要点：常驻/非常驻双模**

主控台**不是必须的**。轻弹窗与控制台窗口在完全没有后台进程时也能工作。主控台在跑时，右键动作会「推」到主控台弹原生模态框，体验更统一；主控台没跑，就走独立的临时卡片，功能不降级。

```
右键动作触发
     │
     ├─ 探测 127.0.0.1:5170 存活？ ── 是 ─→ 结果 POST 到主控台 → 前端弹模态框（带更多操作按钮）
     │                                  并对安装/录屏类任务推送实时日志（SSE）
     │
     └────────────────────────── 否 ─→ 生成临时 HTML 卡片（%TEMP%/apktool/<hash>.html）
                                       → 系统默认浏览器打开 → 关闭即可，零常驻
```

## 3. 信息架构与导航

主控台为**左侧导航 + 右侧内容区**，导航严格按需求稿的功能地图组织，二级可折叠。导航项上带「需设备」标记，无设备时设备域整体灰置但可点击（点了给出连接引导）。

## 4. 全局元素

### 4.1 顶栏
- **设备选择器**：显示 `型号 (序列号尾号)`；点开列出全部设备（状态点：绿=在线 / 灰=离线 / 黄=未授权）；底部有「+ 无线连接」
- **刷新**：全局刷新（重新拉设备与应用列表）
- **命令日志**：抽屉开关，红点提示有失败命令
- **设置**：跳设置页

### 4.2 命令日志抽屉（重要）
每条记录一行：`[时间] $ 命令  | 耗时 | 退出码 | 复制按钮`；失败行红底；点行展开看完整 stdout/stderr。
**这是「不猜命令」原则的载体** —— 出了任何问题，用户自己就能看到实际执行了什么。

### 4.3 关键信息条（Key Bar）
所有信息展示类界面的顶部组件，统一样式：

```
┌─────────────────────────────────────────────────────────────────────┐
│  com.jxw.xwsf                                          [复制包名]   │
│  ⬤ 新网易词霸   v3.2.1 (build 3210)                                 │
│  targetSdk 35 · minSdk 24 · arm64-v8a+x86_64 · 68.4 MB · 正式签名   │
└─────────────────────────────────────────────────────────────────────┘
```
第一行包名（等宽字体，最大号），第二行版本名 + 版本号，第三行摘要标签。**这三行在任何滚动状态下吸顶。**

### 4.4 反馈规范

| 场景 | 反馈形式 | 停留 |
|---|---|---|
| 轻量成功（复制、截图完成） | 右下角 Toast | 2s 自动消失 |
| 有产物的成功（导出 APK） | Toast + 「打开所在目录」按钮 | 6s |
| 失败 | 右上角红色卡片，含原因 + 建议 + 重试按钮 | 需手动关 |
| 长任务（安装/录制） | 内联进度条 + 计时 + 实时日志尾 | 到结束 |

**交互细节**
- 搜索框：输入即过滤（150ms 防抖），匹配 **包名 + 应用名**；空格分词为 AND；命中字符黄色高亮；`Esc` 清空
- 列表：虚拟滚动，支持 ↑↓ 键移动选中、Enter 打开「启动组件」
- 默认只列第三方应用（开关切换），列表顶部显示计数「共 87 个应用（已过滤 3）」
- 危险操作（清数据/卸载）弹内联确认条而非系统框：
  ```
  ⚠ 确认清除 com.jxw.xwsf 的全部数据？该操作不可撤销。
     输入包名以确认：[________________]   [取消] [确认清除]
  ```
  需**粘贴/输入包名**才可点击确认 —— 防止手抖，且比纯弹框更防误触

### 5.1.1 签名区块 · 两级加载（避免"点了没反应"）

签名信息天然分两步拿：**摘要便宜、完整信息贵**（要下载 APK）。界面把这两步显式分开，让用户先有内容、再有精度，而不是转圈等 2 秒。

**时序**
```
选中应用
   │
   ├─ 0ms    签名区块先渲染骨架行：方案 ‹…›   标识 ‹…›   证书主题 ‹…›
   │
   ├─ ~300ms 快路径回来（dumpsys package）→ 立刻填上「方案 v2 · 标识 da3a4721」
   │         并显示一行浅色小字：正在拉取完整证书信息…（可点「跳过」）
   │
   ├─ 1~2s  完整路径回来（pull base.apk → 本地解析）→ 补全 DN / SHA-256 / 有效期 / 算法
   │         小字换成：完整信息已就绪 · 耗时 1.4s · 来源 设备端 base.apk
   │
   └─ 失败   见下方「三态」
```

**进度表达**：不用转圈，用**渐进填充**。已填好的字段不会因为慢路径失败而回退（摘要仍然有效）。

**「重新拉取」按钮**：缓存命中时显示 `来自缓存 · 1 分钟前`，旁挂一个 `🔄 重新拉取`，处理"设备上刚换了包"的场景。

**三态文案（严格对齐"取不到就不做"）**

| 情况 | 区块显示 |
|---|---|
| 两路都成功 | `v2 ✓ 签名标识 da3a4721 用户签名（非 debug）` + 全部字段 |
| 只有快路径成功 | `v2 ✓ 签名标识 da3a4721` + 灰字 `完整证书信息不可得（无法读取设备端 base.apk）` + `[重试] [改为查看本机 APK 签名]` |
| 两路都失败 | 整块灰置，一行说明：`该设备不支持免 root 读取已安装应用签名` + 折叠的「查看原因」（展开显示 `dumpsys package` 无签名字段、`adb pull` 的实际报错）+ `[复制命令自查] [改为查看本机 APK 签名]`。**不显示任何占位值，不出现"未知/—"糊弄** |

**签名比对交互（D2-13）**
点「⚖ 与本机 APK 比对」→ 选一个本地 APK → 弹对比条结果：

```

│  ⚠ 不同签名                                                          │
│                                                                      │
```

### 5.3 轻弹窗 · 右键解析 APK（核心交互 ①）

**触发**：资源管理器中右键 `.apk` → `APK 工具` → `解析信息`

**时序**：
```
0ms     用户点击菜单 → 系统调起 apk-parser.cmd info-popup "<file>"
~300ms  纯 Python 解析 zip + AndroidManifest（无 adb 依赖，不联网）
~400ms  ① 主控台在跑 → POST /api/popup 推卡片（主控台内模态弹窗）
        ② 未跑      → 写 %TEMP%/apktool/info_<hash>.html → 系统浏览器打开
~1.5s   用户看到完整信息（浏览器冷启动约 1s，主要开销在这里）
```

## 6. 关键流程图

### 6.1 右键解析 APK

```
用户右键 .apk → 「APK 工具 / 解析信息」
        │
        ▼
  apk-parser.cmd info-popup "<path>"
        │
        ▼
  纯 Python 读 zip → 解析 AndroidManifest(二进制 AXML) → 组装 dict
        │           （失败 → 尝试 aapt2 dump badging 兜底）
        ▼
  127.0.0.1:5170 存活？
   ├─ 是 → POST /api/popup/info  →  主控台弹模态卡（带跳转启动器按钮）
   └─ 否 → 渲染临时 HTML → start/open/xdg-open 打开
        │
        ▼
  用户看到信息卡（可复制包名 / 直接安装 / 提取图标）
```

### 6.2 双击安装

```
用户双击 .apk → 系统按关联调起 apk-parser-install.cmd "<path>"
        │
        ▼
  分配/复用控制台窗口（Windows: cmd /k   macOS: osascript Terminal   Linux: x-terminal-emulator）
        │
        ▼
  ① 环境检查(adb) → ② 解析 APK → ③ 设备枚举(0/1/N 分支) → ④ 预检
        │
        ▼
  ⑤ adb install（实时输出） → ⑥ 结果判定
        │
        ├─ 成功 → 绿字结论 + [L]看日志 [O]开应用 → 等按键 → 关窗
        └─ 失败 → 错误码中文化 + 建议 + 交互式补救([D]降级/[U]卸载/[C]复制命令)
```

### 6.3 启动任意组件

```
选中应用 → 启动器页 → 拉取组件列表(pm dump 解析)
        │
        ▼
  选中组件 → 表单自动填充(-n) → 用户按需加 action/data/extras
        │
        ▼
  命令预览实时更新（用户全程可见将要执行什么）
        │
        ▼
  点「启动」→ am start [-W] → 结果条(成功: 耗时 / 失败: 原因+建议)
        │
        ▼
  写入历史 → 可一键重发 / 存为「我的入口」
```

### 6.4 获取已安装应用签名（免 root）

```
选中应用（或切到应用详情）
        │
        ├─ ① 快路径  adb shell dumpsys package <pkg>
        │      解析：apkSigningVersion=N      → 签名方案
        │             signatures=[hex]         → 签名标识
        │      ~300ms 出结果 → 立即填入区块
        │
        └─ ② 完整路径（与「导出已装 APK」共用，不重复下载）
              adb shell pm path <pkg>          → 取 base.apk 路径
                 ├─ 多个 split？ → 只取 base.apk（签名仅在 base）
              adb pull <apkpath> cache/apk/<pkg>-<vc>.apk
                 进度 → 界面内联进度条（可取消）
              本地解析（与解析本机 APK 完全同一套代码）
                 方案 v1/v2/v3 · 签名者数量 · 证书 DN · SHA-256/1 · 有效期 · 算法
                 → 补全区块
                 → 结果按「包名+versionCode」写入 cache/signature/

     任一步失败 → 明确显示失败在哪一步 + 原始报错 + 替代入口，
                  不申请 root，不填占位值
```

> 复用的价值：`②` 拉下来的 `cache/apk/<pkg>-<vc>.apk` 同时也是「导出已装 APK」的产物，
> 所以「看签名」和「导出 APK」是**同一次下载**，不会重复消耗带宽。

### 6.5 签名比对（本机 APK ↔ 设备已装）

```
选本机 APK → 解析签名（本地，完整）
        │
        ▼
取设备端签名：优先用缓存的完整结果；无缓存则走 6.4
        │
        ▼
逐字段比对：签名标识 / SHA-256 / 证书 DN / 签名方案
        │
        ├─ 关键字段齐全且全部一致 → ✅ 同一签名
        ├─ 关键字段齐全且有差异   → ⚠ 不同签名（差异字段高亮 + 可能原因）
        └─ 字段不齐（设备端只有标识）→ ❓ 无法判定（说明缺哪个字段，建议拉取完整信息后重试）
```

## 7. 状态设计（空态 / 加载 / 错误）

| 状态 | 呈现 |
|---|---|
| **无设备** | 内容区中央：设备插画 + "未检测到设备" + 三个排查步骤（USB调试是否打开 / 是否授权弹窗 / 试试 `adb kill-server`）+ [重新检测]（同时展示 `adb devices` 原始输出，供自查） |
| **设备未授权** | 黄条："设备已连接但未授权，请在设备上点击『允许 USB 调试』" + 实时轮询，授权后自动消失 |
| **多设备歧义** | 顶栏设备选择器闪一下 + 黄条："检测到 3 台设备，请先选择目标设备" |
| **应用列表加载中** | 骨架屏（灰条），不用转圈，避免布局跳动 |
| **组件列表为空** | "该应用没有导出/可启动的组件" + 提示可勾选「显示不可导出组件」（了解用途） |
| **解析失败** | 卡片形式给：错误摘要 + 可能原因 + 原始异常折叠区 + [用 aapt2 重试] |
| **签名不可得（受限 ROM）** | 签名区块灰置 + 一行结论「该设备不支持免 root 读取已安装应用签名」+ 折叠「查看原因」（显示哪一步失败与原始报错）+ 替代入口「查看本机 APK 签名」。**绝不显示占位值/猜测值** |
| **签名拉取中** | 渐进填充：快路径结果先上屏，未到字段显示骨架行 + 浅色小字进度，**不用遮罩也不阻塞其它区块** |
| **adb 命令超时** | 红卡片："命令 20s 未响应（adb 可能卡死）" + [复制命令] [重启 adb server] |
