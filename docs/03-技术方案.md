> 版本：v0.1（设计评审稿）
> 配套：`01-需求设计稿.md`、`02-交互设计稿.md`

---

## 1. 技术选型

| 层 | 选型 | 理由 | 被否方案 |
|---|---|---|---|
| 核心逻辑 | **Python 3.8+，零第三方依赖** | 跨平台一致；标准库已够用（`zipfile` 读 APK、`struct` 解析 AXML、`subprocess` 调 adb、`http.server` 起服务）；与你已有 `auto-record` 的 Python 栈一致 | 纯 shell：跨平台适配量爆炸；Node/Go：机器上没现成运行时 |
| 主控台 GUI | **本地 Web UI**（后端 `http.server`，前端原生 HTML/CSS/JS，无构建） | 界面表现力强、易做得好看、改样式不用重编译；本机访问无安全问题；浏览器即调试器 | Tkinter：表格/树/表单写复杂了很痛苦，样式受限；PyQt：依赖重；Electron：体积大 |
| 轻弹窗 | **临时 HTML 单文件 + 系统默认浏览器**（服务在跑时改为服务内模态） | 秒开、零常驻、跨平台无差异 | 系统原生弹窗：Windows/macOS/Linux 三套实现，收益低 |
| 控制台窗口 | **系统终端**（cmd / Terminal.app / x-terminal-emulator） | 实时日志流最自然；用户已明确接受 cmd 窗口；零额外依赖 | 自绘 GUI 日志窗：要处理滚动/编码/关闭，得不偿失 |
| APK 解析 | **纯 Python 自研 + aapt2 可选交叉校验** | 不依赖 SDK 也能用（右键场景往往没配 SDK）；有 aapt2 时验证准确性 | 只调 aapt：无 SDK 就废；只自研：AXML 边界情况需校验兜底 |
| 与服务通信 | **HTTP + JSON；实时流用 SSE** | 比 WebSocket 简单、可读、curl 可调；SSE 天然适合单向日志流 | WebSocket：本场景用不上双向 |
| 设备访问 | `adb` 命令行（`subprocess`） | 唯一官方途径，不引第三方库 | python-adb：依赖 usb 库，Windows 上装包麻烦 |

**唯一硬依赖：能用的 `adb`（设备域功能才需要）。本机域功能与 adb 完全解耦。**

```

│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────────┐  │

┌─────────────────────────────────▼──────────────────────────────────────────┐

│  └──────────────────────┘ └──────────────────────────────────────┘        │
└─────────────────────────────────┬──────────────────────────────────────────┘

┌─────────────────────────────────▼──────────────────────────────────────────┐
│  平台层 (platform/)                                                        │
│  paths.py(路径) · shell.py(终端投递) · adb_finder.py · scrcpy_finder.py    │
│  menu_win.py(注册表) · menu_mac.py(Quick Action) · menu_linux.py(.desktop) │
└────────────────────────────────────────────────────────────────────────────┘
```

**分层铁律**
1. `core/` 里**不得** `import tkinter/web/platform 具体实现**，不得出现 `if sys.platform == ...`（要平台差异 → 通过 `platform/` 的接口）
2. `core/` 的函数尽量是**纯函数或明确 IO 边界的函数**，返回 `dataclass`，便于单测
3. 所有外部命令调用统一走 `platform/shell.py::run()` —— 一处加超时、加日志、加错误包装

## 4. CLI 命令契约

所有 GUI 能力都有对应子命令。**`--json` 输出为稳定契约**（只增字段不删）。

```
apktool.py <group> <command> [args] [--json] [--device <serial>]

# 本机域
  apk info      <file> [--json]                 # 解析信息
  apk popup     <file>                          # 右键入口：弹信息卡
  apk icon      <file> [-o out.png] [--size N]  # 提取图标
  apk diff      <a.apk> <b.apk> [--json]        # 双包对比
  apk sign      <file> [--json] [--verify]      # 签名信息（本地文件，完整）
  apk slim      <file> [--json]                 # 体积构成
  apk scan      <dir> [--json] [--csv out.csv]  # 批量解析

# 设备域
  device list   [--json]
  device info   [--json]
```

**关键命令示例**

```bash
# 右键菜单实际调用的命令（必须快、必须无副作用）
python apktool.py apk popup "D:\build\out\app-jxwgb-release.apk"

# 双击安装实际调用的命令
python apktool.py install one "D:\x.apk" --console

# 启动任意组件（界面「复制命令」按钮复制出来的就是这一行）
python apktool.py launch start com.jxw.xwsf/.ui.WifiListActivity \
  --action android.intent.action.VIEW --data "xwsf://scan?ssid=test" \
  --flag NEW_TASK --es ssid test --ez autoScan true --wait

# 供脚本消费
python apktool.py apk info app.apk --json | python -c "import sys,json;print(json.load(sys.stdin)['versionCode'])"

# 签名：免 root 读已安装应用的签名（快路径 0.3s / 完整路径 1~3s）
python apktool.py app sign com.jxw.student.study --json
python apktool.py app sign-cmp com.jxw.student.study --apk "D:\build\app-release.apk"
```

## 5. HTTP API 契约（主控台）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | `{ok, version}` —— 右键脚本用它探测服务是否存活 |
| GET | `/api/devices` | 设备列表 |
| GET | `/api/apps?filter=&system=0` | 已装应用列表 |
| GET | `/api/apps/<pkg>` | 应用详情 |
| GET | `/api/apps/<pkg>/signature?fast=1` | **签名信息**。`fast=1` 只走快路径（dumpsys，~0.3s）；缺省走完整路径（必要时 pull）；命中缓存直接返回，响应带 `source=cache\|device\|dumpsys` |
| POST | `/api/apps/<pkg>/signature/refresh` | 强制重新拉取（忽略缓存） |
| POST | `/api/apk/signature/compare` | 签名比对，body 支持 `{apk: 路径}` 或 `{device_serial, pkg}` 组合；返回 `{verdict: same\|different\|undetermined, fields:[…]}` |
| POST | `/api/apps/<pkg>/action` | 强制停止/清数据/卸载/导出 |
| GET | `/api/launch/components?pkg=&type=` | 组件列表 |
| POST | `/api/launch/start` | 启动（body = Intent 模型） |
| POST | `/api/launch/dry-run` | 只回命令预览（前端实时预览走这个，150ms 防抖） |
| POST | `/api/capture/screenshot` | 截图 |
| POST | `/api/capture/record` | `{op:"start"\|"stop"}` |
| GET | `/api/capture/artifacts` | 产物列表 |
| POST | `/api/install` | 安装（返回 taskId） |
| POST | `/api/apk/parse` | 解析本机 APK（body: 路径或上传） |
| POST | `/api/popup/info` | ★ 右键脚本推卡片进来 |
| GET | `/api/tasks/<id>/events` | **SSE** 实时进度/日志 |
| GET | `/api/log/cmd` | 命令日志 |
| POST/GET | `/api/menu/state` · `/api/menu/apply` | 菜单注册状态/应用 |
| GET | `/api/sys/doctor` | 环境自检 |

**安全的本地服务**
- 默认 `bind 127.0.0.1`，绝不允许 `0.0.0.0`（除非用户显式设置且给出风险提示）
- 涉及文件路径的接口，服务端做**规范化 + 白名单根目录校验**，拒绝路径穿越
- 右键脚本推送卡片时带一次性 `token`（服务启动时写入 `~/.apk-parser/token`，文件权限 600），防其它本机程序乱推
- 所有写操作（安装、卸载、注册表）都在响应里回显「将要执行的命令」

## 6. 跨平台适配矩阵

| 能力 | Windows | macOS | Linux |
|---|---|---|---|
| adb 探测 | `PATH` → `D:\SDK\platform-tools` → `%LOCALAPPDATA%\Android\Sdk\...` | `PATH` → `~/Library/Android/sdk/platform-tools` | `PATH` → `~/Android/Sdk/platform-tools` → 包管理器路径 |
| 打开文件/目录 | `os.startfile` / `explorer /select,` | `open` / `open -R` | `xdg-open` |
| 起控制台窗口 | `cmd /c start "" cmd /k <cmd>` | `osascript` 调 Terminal | `x-terminal-emulator` / `gnome-terminal` / `konsole` / `xterm` 依次探测 |
| 右键菜单 | 注册表 `HKCU\Software\Classes\SystemFileAssociations\.apk\shell\...`（无需管理员） | `~/Library/Services/*.workflow`（生成 Automator Quick Action plist，用户需在系统设置中启用） | `~/.local/share/file-manager/actions/*.desktop` |
| 双击关联 | `.apk` → ProgId + `OpenWithProgids`；默认关联受 UserChoice 保护需用户确认一次 | Quick Action / 用 `duti` 可达但非默认安装 | `~/.local/share/applications/*.desktop` + `xdg-mime default` |
| 配置目录 | `%APPDATA%\apk-parser` | `~/Library/Application Support/apk-parser` | `~/.config/apk-parser` |
| 中文字体渲染（控制台） | 需 `chcp 65001` 或设置 `PYTHONUTF8=1` | 天然 UTF-8 | 天然 UTF-8 |
| 进程终止 | `taskkill /PID /T /F` | `kill -TERM` | `kill -TERM` |

> Windows 控制台编码坑（已在 `auto-record` 里踩过）：脚本里 `print` 非 GBK 字符会 `UnicodeEncodeError` 直接杀进程 —— 统一在入口处 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`，并在 `.cmd` 里先 `chcp 65001 >nul`。

## 7. 签名获取方案（含真机实测结论）

> 需求约束：**不申请 root**。若已安装应用的签名在不 root 的前提下取不到，就不做这个功能。
> 所以这一节先用真机验证"能不能取到、怎么取、多贵"，再决定实现。

### 7.1 实测结论（Z21 / Android 13 / SDK 33，adb 1.0.41）

| 探测项 | 结果 | 结论 |
|---|---|---|
| `dumpsys package <pkg>` 是否输出证书信息 | ⚠ **只有 3 个字段**：`apkSigningVersion=2`、`signatures=PackageSignatures{… version:2, signatures:[da3a4721], past signatures:[]}`、`Signing KeySets: 18`。**没有** `Signer #1 certificate DN` / SHA-256 digest 行 | `dumpsys` 单独**不够**：只能给"签名方案 + 签名标识哈希"，拿不到 DN 与 SHA-256 |
| `pm path <pkg>` | ✅ `package:/data/app/~~gruDpyOQ…/com.jxw.student.xueqing-QX8M04…/base.apk` | 路径可得 |
| `ls -l` 设备端 APK 权限 | ✅ `-rw-r--r-- 1 system system`（`/system/preloadapp` 下为 `root root`，同样 644） | 世界可读 |
| `cat <apkpath>` | ✅ rc=0，头部 `PK\x03\x04` 正确 | 文件内容可读 |
| **`adb pull <apkpath>`** | ✅ **rc=0**。27.5 MB → 0.745s；54.2 MB → 1.467s（**约 35 MB/s**） | ✅ **免 root 完全可行，且很快** |

**由此定案的两条路径**

| 路径 | 命令 | 成本 | 产出 | 用途 |
|---|---|---|---|---|
| **① 快路径** | `dumpsys package <pkg>` | ~0.3s，无下载 | 签名方案版本、**签名标识哈希**（如 `da3a4721`）、past signatures 有无 | 秒出内容；**同签名快速判定**（实测 `com.jxw.student.xueqing` 与 `com.jxw.student.study` 标识同为 `da3a4721` → 同一签名，一眼可判） |
| **② 完整路径** | `pm path` → `adb pull base.apk` → 本地解析 | 1~3s（按包体），有下载 | 证书 DN、SHA-256/SHA-1、有效期、密钥算法与长度、是否 debug、多签名者 | 完整签名区块；与 `L1-3`（本机 APK）**共用同一套解析代码** |

**关键实现要点**

1. **一次 pull 两用**：拉下来的 `cache/apk/<pkg>-<versionCode>.apk` 同时就是「导出已装 APK」的产物，两个功能不重复下载。
2. **split APK 只取 base**：`pm path` 返回多行（base + `split_config.*`）时，只取 `base.apk` —— 签名只存在于 base，避免多文件下载与误判。
3. **缓存键 = 包名 + versionCode**：设备上换了包，versionCode 变了自然失效；界面提供 `🔄 重新拉取` 手动强制刷新。
4. **绝不 root 兜底**：两条路都不通（受限 ROM / pull 被拒）时，按 `D2-12` 明确报错并停手，不给占位值。

### 7.2 难点与对策

| # | 难点 | 方案 |
|---|---|---|
| 1 | **二进制 AndroidManifest 解析**（AXML） | 标准库 `struct` 手写 chunk parser：解析 `RES_XML_TYPE` → `START_NAMESPACE` / `START_ELEMENT` / `ATTRIBUTE`，用 string pool 还原属性名与值；遇到 `TYPE_REFERENCE` 的 `versionName`（资源引用）时，去 `resources.arsc` 里按 `default`/`zh-CN` 配置查回字符串 |
| 2 | **应用名多语言** | 解析 `arsc` 的 `RES_TABLE_TYPE` 全局字符串池 + 各 locale，优先级：`zh-CN` → `zh` → `en` → `default` |
| 3 | **签名解析（零依赖）** | 统一入口 `core/apk/cert.py`，**本机 APK 与已装 APK 走同一份代码**：<br>· v1：读 `META-INF/*.(RSA\|DSA\|EC)` → 手写最小 DER 解析取 `Subject RDN` / `notBefore` / `notAfter` / 公钥算法与位长；指纹用 `hashlib` 对证书 DER 直接算（**无需 `cryptography`**）<br>· v2/v3：定位 `APK Sig Block 42`（文件尾 `0x06054B50` → EOCD → 中央目录偏移，再回溯 magic），取 signer 的 `signedData.certificates`，同样走上面的 DER 解析<br>· 权威结论：`apksigner verify` 可用时并列展示「已验证有效 / 未验证」，**不把自家解析说成"已校验"** |
| 4 | **`dumpsys package` 组件抽取** | 输出格式随 ROM 有差异 → 用「状态机式逐行解析」而非单一正则：先定位 `Activity Resolver Table:` / `Service Resolver Table:` 段，再按 `filter`/`ComponentInfo{...}` 行抽取；解析失败回退正则 `([a-zA-Z0-9_.]+/[a-zA-Z0-9_.$]+)`；两条路都不行则提示「该 ROM 不支持组件列表，请用 `pm dump` 模式」 |
| 5 | **已装应用签名的两路降级** | ① 快路径正则抽 `apkSigningVersion=(\d+)` 与 `signatures=[…signatures:\[([0-9a-f]+)\]…]`；两条都抽不到即视为"该 ROM 不支持"；② 完整路径见 §7.1。前端按「渐进填充」呈现（见交互稿 §5.1.1），**中间态不阻塞、失败不回退已填字段** |
| 6 | **`am start` 参数拼接与转义** | 集中到 `core/launch/intent.py::to_am_args()`，唯一真相。所有 value 走统一 shell 引号转义（Windows 下 `subprocess` 用 list 形式避开 shell；预览字符串另做人类可读版本） |
| 7 | **SSE 实时日志** | `ThreadingHTTPServer` + 每任务一个 `queue.Queue`，SSE handler 阻塞读队列；任务结束推 `event: end` 让前端收尾；心跳注释行每 15s 防中间层断连 |
| 8 | **安装进度** | `adb install` 本身不吐百分比 → 大文件先手动 `adb push`（解析 `[ 62%]`）再 `pm install`（或 `adb install --no-streaming` 观察进度），小文件直接 `install -r` 用不确定进度 + 计时 |
| 9 | **多设备并发安装** | `concurrent.futures.ThreadPoolExecutor`，每设备一条独立 adb 调用与独立 SSE 通道，互不阻塞 |
| 10 | **服务单实例** | 启动时尝试绑定端口；已占用则读 `~/.apk-parser/server.json` 拿 pid 验证是否为自家服务；是则「已在运行，直接打开页面」，不是则报端口冲突并建议改端口 |
| 11 | **adb 卡死** | 所有调用强制 `timeout`；超时后 `taskkill /T /F` 清理子进程树；连续 2 次超时提示「建议重启 adb server」，一键 `adb kill-server && adb start-server` |

## 8. 能力注册表（可扩展性的核心）

`registry.py` 中每个能力是一条声明：

```python
CAPABILITY = Capability(
    id="launch.start",
    group="device.launcher",          # 决定导航归属
    title="启动组件",
    needs_device=True,
    risk="low",                       # low | confirm | dangerous
    cli="launch start",
    api=("POST", "/api/launch/start"),
    form=FormSpec(fields=[
        Field("component", "组件", "text", required=True),
        Field("action", "Action", "text"),
        Field("flags", "Flags", "multiselect", options=FLAG_PRESETS),
        Field("extras", "Extras", "kv-list", types=["string","int","bool","float","long","uri"]),
        Field("wait", "计时(-W)", "bool", default=False),
    ]),
    renderer="form+command-preview",  # 前端渲染策略
)
```

**前端渲染策略**（`renderer` 字段）预置 5 种，覆盖 90% 未来需求：
`table` / `form+command-preview` / `log-stream` / `gallery` / `wizard`。
新增功能若属这 5 类，**前端零改动**；只有全新交互形态才需要加 renderer。

风险等级驱动 UI：`confirm` 弹内联确认条，`dangerous` 要求输入包名确认。

## 11. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| 纯 Python AXML 解析在个别畸形包上失败 | 右键解析不可用 | aapt2 兜底 + 明确错误提示 + 「用 aapt2 重试」按钮 |
| 各 ROM `dumpsys` 输出格式差异 | 组件列表不准 | 双解析路径 + 解析失败显式告警（不静默给空列表） |
| Windows 默认打开方式受 UserChoice 保护 | 「双击安装」需用户操作一次 | 设计上不承诺自动设置，改用「打开方式」引导 + 图文步骤 |
| macOS Quick Action 需手动在系统设置启用 | macOS 右键体验打折 | 界面内给出开启指引；同时提供 CLI 兜底 |
| 零依赖限制签名解析深度 | 只能给指纹/主体/有效期，不能做完整性校验 | 有 `apksigner` 时用它做权威校验，二者结果并列展示 |
| **个别 ROM 上 `dumpsys package` 不输出签名字段** | 快路径拿不到标识 | 已实测确认这是**常态**（Z21 上就没有 Signer 块）→ 设计上快路径只当"锦上添花"，完整路径（pull+本地解析）才是主路径，实测免 root 且 35 MB/s |
| **个别 ROM 限制 `/data/app` 读取** | 完整签名拿不到 | 按 `D2-12` 明确报错并停手（不 root、不猜）。因为"拉不到"与"包本身没签名"在视觉上必须区分开，所以错误文案要带原始报错 |
| 拉包体积大（上百 MB 的应用） | 看签名要等 | 只拉 `base.apk`；带进度与可取消；结果缓存复用；与「导出 APK」共享同一次下载 |
| **签名缓存被误用** | 设备上换了包但显示的签名是旧的 | 缓存键含 `versionCode`；界面显示 `来自缓存 · N 分钟前` + `🔄 重新拉取`；安装操作后自动失效对应缓存 |
| 服务端口被占 | 主控台起不来 | 单实例检测 + 自动换端口 + 明确提示 |
