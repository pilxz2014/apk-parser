# APK Parser Toolkit

Android 开发/测试日常的 **APK 解析 + 设备操控** 桌面工具箱。
鼠标原生操作（右键 / 双击 / 图形界面）为主，命令行与脚本为辅，Windows / macOS / Linux 同一套代码。

> 当前状态：**v0.1.0 已实现**（四大块功能全部可用，34 个能力打通，真机 Z21 实测通过）

---

## 快速开始

**最省事的方式（Windows）**：双击根目录的

- `start.bat` —— 一键启动。**会先停掉上一次的服务再启动**（重启式启动），浏览器自动打开；
  那个控制台窗口就是服务本体，关掉窗口 / Ctrl+C 即停止
- `stop.bat` —— 一键停止

（老的 `run-web.cmd` / `stop-web.cmd` 仍在，内部委托给上面两个脚本；`run-web.cmd` 供右键菜单等老入口兼容。）

命令行等价：

```bash
python apktool.py web restart        # = start.bat：先停旧实例再启动（浏览器自动打开）
python apktool.py web stop           # = stop.bat
python apktool.py web start          # 启动（已在运行则直接复用，不重启）
python apktool.py sys doctor         # 环境自检（adb / aapt2 / scrcpy / ffmpeg 探测）
python apktool.py sys menu install   # 注册右键菜单（Windows 只写 HKCU，不需要管理员）
python apktool.py sys menu install --style flat   # 若级联子菜单不展开：改用平铺保底样式
python apktool.py sys menu status    # 查看菜单注册状态（会显示当前是级联还是平铺）
python apktool.py apk info app.apk   # 命令行解析
```

**右键菜单有两种样式**（Windows，均只写 `HKCU`、不需要管理员）：

| 样式 | 效果 | 何时用 |
|---|---|---|
| `cascade`（默认） | 右键 `.apk` → 「APK 工具」→ 展开子菜单（6 项） | 常规选择，菜单干净 |
| `flat` | 6 项直接平铺，标题前缀「APK 工具 · 」 | **保底**：级联若在个别系统上不展开，用它 |

说明：Explorer 的级联子菜单是**悬停时才解析**的，无法在无界面环境下自动验证渲染结果。
`flat` 走的是顶级静态 verb，可见性是确定的 —— 所以留了这条 100% 能显示的后路。

## 实现完成情况

### 四大块功能

| # | 功能 | 状态 | 入口 |
|---|---|---|---|
| 一 | **看应用信息** —— 本机 APK 解析（右键弹卡片，包名 + 版本最大字号）+ 已装应用检索 | ✅ | 右键菜单 / 主控台「本机·APK」「设备·应用」 |
| 二 | **启动任意 Activity/Service** —— 图形化参数编辑 + 实时命令预览 | ✅ | 主控台「设备·启动器」`launch start` |
| 三 | **录屏与截图** —— 截图 / screenrecord / scrcpy 镜像 / logcat | ✅ | 主控台「设备·捕获」 |
| 四 | **安装支持** —— 右键安装、双击弹控制台窗口、预检 + 失败中文化 | ✅ | 右键菜单 / 主控台「设备·安装」 |

### 已实现的 34 个能力（7 个分组）

- **本机·APK**（7）：解析、信息卡片、签名、双包对比、体积构成、批量解析、提取图标
- **设备·应用**（9）：设备列表、应用列表、应用详情、**应用签名（免 root）**、签名比对、导出 APK、强制停止、清除数据、卸载
- **设备·启动器**（5）：组件列表、启动组件、发送广播、启动历史、我的入口
- **设备·捕获**（5）：截图、录屏、实时镜像、日志、产物管理
- **设备·安装**（3）：安装前预检、安装、失败诊断
- **设备·文件**（1）：文件浏览 / push / pull
- **系统**（4）：菜单注入、环境自检、设置、主控台

### 选 APK 的三种方式（主控台）

1. **拖进来** —— 把 `.apk` 直接拖到浏览器页面上，松手即解析。
   浏览器不给拖入文件的真实路径，所以服务端按「文件名 + 体积」在本机常见目录
   （桌面/文档/下载/图片 + 项目目录 + 上次用的目录）里找回来，实测 43ms 命中；
   找不到会提示改用「浏览…」
2. **浏览…** —— 服务端弹原生文件框（浏览器自己拿不到真实路径），选中后自动解析，
   并记住目录，下次直接落在那儿
3. **粘路径** —— 直接把完整路径贴进输入框，回车即可

### 四种交互载体

| 载体 | 说明 |
|---|---|
| **主控台**（Web UI） | 本地 Web，零依赖零构建，绑 `127.0.0.1`、单实例、token 校验 |
| **轻弹窗** | 右键 `.apk` 秒开信息卡：有主控台就推过去，没有就开临时 HTML —— 零常驻进程 |
| **控制台窗口** | 双击 `.apk` → 独立 cmd/Terminal 窗口跑安装，实时日志 + 进度百分比；参数与 `adb install` 对齐（`-t` 允许 test 包 / `-r` 覆盖 / `-d` 允许降级 / `-y` 不询问），**版本比设备低时先问一句再装** |
| **命令行** | 全部能力都有子命令，`--json` 输出是稳定契约，可直接接进 `D:\bat\*.sh` 做断言 |

## 核心设计要点（速览）

- **四种载体分工**：主控台（常驻 Web UI）/ 轻弹窗（右键，秒开、零常驻）/ 控制台窗口（双击，实时日志流）/ 命令行（可被脚本消费）
- **两个一级域**：按「是否需要设备」划分 —— 本机域（解析/分析）与设备域（应用/启动器/捕获/安装/文件）
- **一眼看到重点**：所有信息界面顶部固定「关键信息条」，包名 + 版本名/号 最大字号且吸顶
- **不猜命令**：界面上每个动作都显示将要执行的真实命令，可一键复制进 `.sh` 脚本
- **不静默失败**：失败必给「发生了什么 + 为什么 + 怎么办」，安装失败附中文释义与一键补救
- **易扩展**：能力注册表（`registry.py`）+ 6 种预置前端渲染策略，加功能通常不用改前端

## 签名信息（免 root）

**本机 APK 签名**：直接本地解析文件，零成本、字段完整（方案 v1/v2/v3、证书 DN、SHA-256/SHA-1、有效期、算法、是否 debug）。

**已安装应用签名**：不申请 root，走两条路 ——

| 路径 | 命令 | 实测成本 | 拿到什么 |
|---|---|---|---|
| 快路径 | `dumpsys package <pkg>` | ~0.2s | 签名方案版本、签名标识哈希（可快速判同） |
| 完整路径 | `pm path` → `adb pull base.apk` → 本地解析 | ~0.4s | 证书 DN、SHA-256/SHA-1、有效期、算法、是否 debug |

**真机实测（Z21 / Android 13 / SDK 33）**：`dumpsys package` 在这台 ROM 上**不输出证书信息**（只有 `apkSigningVersion` 和 `signatures` 哈希），
但 `adb pull /data/app/…/base.apk` **免 root 可用且很快**，连 `/system/preloadapp` 下的都能拉。
→ 所以完整签名以"拉回本地自解析"为主路径，且与「导出已装 APK」**共用同一次下载**。

**交叉验证**：设备拉回来的 `base.apk` 本地解析出的证书 SHA-256，与本机同名 APK 的解析结果
**逐字节一致**（`16:95:9B:9F:…:24:56`），并与设备端 dumpsys 的签名标识哈希互相印证。

**取不到时就不做**：两条路都失败（受限 ROM / pull 被拒）时，界面明确显示"该设备不支持免 root 读取已安装应用签名"，
展开可看到失败在哪一步与原始报错，并给替代入口。**绝不申请 root、绝不显示占位值或猜测值。**

## 已拍板的默认选择

设计稿里留的 4 个待确认项，按以下默认执行（都可改）：

1. **主控台形态**：本地 Web UI（零依赖零构建），不是 Tkinter
2. **双击安装**：**不改默认打开方式**，只注册成「打开方式」候选 —— 想双击安装就手动选一次
3. **主控台端口**：默认 `5170`，被占用则自动顺延 20 个；端口、产物目录等都能在「系统·设置」里改
4. **优先级**：本机域（解析 + 右键）与设备域并行推进，先打通链路再补体验

## 环境依赖

工具本身只需要 **Python 3.8+**，核心解析**零第三方依赖**（AXML / resources.arsc / DER 证书 / APK 签名块全是手写的）。
以下为可选增强（缺了只影响对应功能，界面会红标并给下载指引）：

| 工具 | 用途 | 本机当前状态 |
|---|---|---|
| `adb` | 设备域全部功能 | ✓ `D:\SDK\platform-tools` |
| `aapt2` | APK 解析交叉校验 | ✓ `D:\SDK\build-tools\37.0.0` |
| `apksigner` | 签名有效性的权威结论 | ✓ `D:\SDK\build-tools\37.0.0` |
| `scrcpy` | 实时镜像 / 边镜像边录 | ✓ `D:\Program Files\scrcpy\scrcpy-win64-v3.3.4` |
| `keytool` | 签名解析交叉校验 | ✓ JDK 1.8 |
| `ffmpeg` | 录屏转 GIF | ✗ 未安装（可选） |

## 与既有工具的关系

- `D:\bat\batch_install.sh` → 本工具的「批量安装」覆盖它（多设备/预检/失败中文化）
- `D:\bat\auto-record`（脚本编辑器）→ 互补：本工具提供「复制命令」，可直接粘进那边的脚本步骤
- `D:\bat\*.sh` 测试脚本 → 本工具 CLI 支持 `--json`，可在脚本里调用做断言

## 目录速查

```
apktool.py              入口（也支持 python -m apkparser）
apkparser/
  cli.py                命令行（全部子命令；--json 是稳定契约）
  registry.py           能力注册表 —— 可扩展性的核心
  config.py             配置读写
  platform/             ★ 唯一允许出现 sys.platform 分叉的地方
    paths.py              跨平台目录计算
    shell.py              统一的命令执行包装（超时/编码/剪贴板/弹控制台）
    finders.py            adb/aapt2/scrcpy/ffmpeg 探测
    menu_win|mac|linux.py 各平台右键菜单注入
  core/                 ★ 与界面完全解耦，可被 CLI/Web/弹窗共用
    apk/                 纯 Python 二进制解析：axml / arsc / der / cert / reader / info / analyze
    device/              adb / apps / signature（免 root 两级）/ tools
    launch/              intent（命令唯一真相来源）/ components / history
    capture/             screen / record / logcat / gallery
    install/             errors（中文化词表）/ precheck / installer
    files.py             push / pull / ls
  web/
    server.py            ThreadingHTTPServer + SSE + 单实例 + 静态服务
    routes.py            ~57 条 HTTP API
    tasks.py             长任务与事件流（可重放）
    static/              前端（原生 JS，零依赖）
  ui/                    popup（信息卡 HTML）/ console（ANSI 彩色终端）
```

`apk.cmd` / `apk.sh` 等根目录脚本是给右键菜单与双击用的薄壳。
